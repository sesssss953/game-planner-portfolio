01 / BRIEF

项目概览

先明确体验目标，再从规则、玩家行为和反馈路径逐层拆解。

01 / CONTEXT

分析对象

《金铲铲之战》S13「双城传说2」赛季；重点观察海克斯强化选择与阵容方向之间的关系。

02 / QUESTION

核心问题

随机选项如何提供新鲜感，同时避免玩家觉得选择无用、规则难懂或决策完全失控？

03 / LENS

分析维度

选择空间、阵容适配、阶段节奏、正反馈，以及休闲玩家与进阶玩家的不同需求。

02 / SYSTEM BREAKDOWN

系统如何影响一局游戏

以下为基于原始拆解文档整理的设计解读；具体版本规则仍应以游戏内实际内容为准。

出现随机选项制造信息不完全与选择压力
玩家作出取舍结合已有棋子、装备与局势判断
调整阵容方向让本局形成差异化构筑
对局反馈结果验证选择，并为下一次决策提供信息

设计价值：随机，但不应失去方向

随机选项可以提高每局的差异性，迫使玩家根据当前局面调整计划，而不是机械复现固定阵容。理想状态下，玩家既能感受到“这局不一样”，又能理解自己为什么做出这个选择。

  • 让不同开局产生不同决策路线。
  • 让选择与已形成的阵容方向发生关联。
  • 通过战斗结果反馈选择的价值。

体验风险：选择成本可能超过理解能力

当选项描述、触发条件或阵容适配关系不够直观时，新手容易依赖外部攻略；如果选择与现有构筑脱节，也可能觉得选项只是随机发放的奖励。

  • 理解成本高：看不懂效果或不知道怎么用。
  • 决策成本高：难以比较多个选项的长期收益。
  • 反馈不清晰：很难判断结果来自决策还是运气。
03 / DESIGN TRADE-OFF

我关注的设计权衡

不是单纯增加提示，而是在保留策略深度的同时，减少无效困惑。

设计目标可能的正向体验需要防范的问题观察信号
提高随机性每局出现不同路线，提升重玩动机玩家认为胜负过度依赖运气玩家是否能说清关键选择的理由
强化构筑联动选项帮助玩家形成阵容方向过度引导导致套路固化、选择单一有效构筑路线是否仍然多样
降低新手门槛更快理解效果与可行策略提示过多，挤压探索与学习空间求助攻略频率、放弃选择比例、学习后的独立决策能力
维持策略上限进阶玩家仍能比较时机、收益与风险提示系统直接给出“唯一正确答案”高水平玩家是否仍存在多种可行解
04 / PROPOSAL

优化提案：阵容理解辅助

把原始报告中“新手阵容引导”的想法，进一步整理为一个可讨论、可验证的小方案。

PROTOTYPE CONCEPT

轻量提示，而不是自动替玩家做决定

当玩家已拥有若干同方向棋子、但尚未形成完整羁绊时，提供一条可主动展开的建议：当前阵容可能的补强方向、相关棋子类型，以及该方向需要承担的机会成本。提示只提供信息，不自动购买、不锁定阵容，也不直接标记唯一最优解。

触发时机识别到明显的阵容方向，且玩家尚未建立完整构筑时；避免每次购买都弹窗。
呈现方式默认一行简短提示，点击后查看羁绊效果、可选补强方向与注意事项。
设计边界允许关闭；不使用“必选”“最强”等绝对化文案，避免干扰进阶玩家。

验证方式

建议先制作可点击的低保真原型，再进行小规模可用性测试。以下指标是待验证假设，不是已经取得的测试结果。

  • 新手能否用自己的话解释提示含义。
  • 从看到提示到做出选择的时间是否缩短。
  • 玩家是否感到更有方向，而非被系统强迫。
  • 关闭提示的比例，以及玩家对提示频率的反馈。

风险与迭代

阵容建议可能受到当前棋子、装备、经济与对手局势共同影响，单看羁绊容易给出片面建议。因此第一版应控制范围，优先验证“看懂提示”而不是追求自动推荐的准确率。

  • 若提示太频繁：增加冷却与主动展开机制。
  • 若建议过于单一：同时呈现两种可行方向。
  • 若玩家不信任提示：展示推荐原因，而非只给结论。

说明：该方案是基于原始拆解报告提出的设计假设，并非游戏官方功能，也未声称经过真实线上数据验证。

05 / REFLECTION

复盘：从“我觉得”走向“可验证”

LEARNING 01

先描述玩家行为

把“系统有趣”拆成玩家看到了什么、做了什么选择、收到了什么反馈。

LEARNING 02

区分观察与假设

玩家痛点需要结合访谈、可用性测试或数据验证；个人体验适合作为问题线索，而不是结论本身。

LEARNING 03

让提案可被推翻

明确目标用户、触发条件、方案边界与验证指标，方便后续根据反馈继续迭代。
